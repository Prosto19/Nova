# NOVA — интерфейс регистрации, этап без нового backend

## Что существует

`server.mjs`: прежний локальный вход по логину/паролю, scrypt, cookie-сессия, три вымышленных аккаунта. Не публикуется в Sites. Роль выдаёт сервер из записи пользователя, а не выбранная карточка интерфейса.

`public/experience.js`: выбор роли → наличие аккаунта → выбор способа входа или регистрация. Роль здесь только подсказка маршрута. Студент может продолжить на ПК или перейти по QR. Преподаватель и деканат используют тот же `/register/` с параметром `role`.

`public/mobile.js`: один клиентский сценарий для всех ролей, профиль/приглашение, демонстрационный код, необязательный Passkey, тестовый пароль, завершение. Не вызывает auth API, не создаёт сессий или полномочий. Четыре вымышленных профиля (два студента, преподаватель, деканат).

## Сохранение

В sessionStorage — выбранный тестовый профиль, этап и редактируемые вымышленные поля, раздельно по сценарию роли. Перезагрузка той же вкладки восстанавливает эти поля. Пользователь явно видит, что нужны только вымышленные данные. Фото — Object URL в памяти; пароль — только поля/оперативная память до завершения/обновления, без localStorage/sessionStorage, сетевой передачи или LLM. Одноразовые коды не сохраняются. Закрытие вкладки не гарантирует восстановление: это sessionStorage, не постоянная регистрационная сессия.

## Границы демонстрации

- Код/приглашение сравнивается локально и ничего не активирует. Серверный срок и одноразовость не имитируются.
- Passkey явно недоступен, не вызывает navigator.credentials.create/get.
- QR регистрации — обычная публичная ссылка, без персональных данных, не одноразовый токен и не вход.
- QR авторизации явно недоступен. Нельзя подтверждать сессию ПК по этой ссылке.
- Завершение не заявляет об успешной регистрации или действительной сессии.
- Учительский и административный доступ не создаётся клиентом.

## Заготовки для следующего этапа (не реализованы)

Новые действия добавляются в существующий сервер, а не в отдельную систему авторизации:

| Действие | Будущий контракт | Требования |
|---|---|---|
| Проверка студенческой записи | POST /api/registration/student/verify | Непрозрачный registrationId, проверка источника, минимум данных до подтверждения |
| Активационный код | POST /api/registration/activate | Код связан с записью; хеш, TTL, лимиты, атомарное одноразовое использование |
| Приглашение сотрудника | POST /api/registration/invitation | Сервер извлекает profileId/role; не принимает клиентскую роль как полномочие |
| Passkey | POST /api/passkeys/options; POST /api/passkeys/verify | Серверный challenge, RP ID, Origin, TTL; хранятся публичный ключ и credential ID |
| Завершение | POST /api/registration/complete | Пароль хешируется существующим безопасным серверным механизмом; атомарное создание записи и сессии |
| QR-вход | POST /api/login/attempt; GET /api/login/attempt/status; POST /api/login/attempt/confirm | Отдельные секреты для ПК и телефона, подтверждённая телефонная сессия, TTL, отмена, consume-once; токен QR не является сессией |
| Помощь | Контекст: roleHint, step, errorCode | Пароль/код/приглашение/фото не передаются LLM; модель не изменяет результат проверки |

Блокировка шага в UI не является защитой. Каждая операция и доступ к профилю проверяются сервером независимо от URL, параметра role и изменённого sessionStorage.

## Локальный запуск

`npm start` — http://localhost:3000.
